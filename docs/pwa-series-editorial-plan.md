# الخطة التحريرية وضبط التداخل لسلسلة PWA

**الحالة:** معتمدة للتخطيط — لا تُنشر أي مقالة من السلسلة قبل اجتياز مراجعة التداخل النصي والموضوعي.  
**المشروع التطبيقي الموحد:** تطبيق مهام عربي صغير، مبني بـ HTML وCSS وJavaScript، ثم يُضاف إليه التخزين المحلي وخصائص PWA ويُنشر على GitHub Pages.  
**الجمهور:** مطوّر مبتدئ يعرف أساسيات HTML وCSS وJavaScript، ولا يحتاج إلى إعادة شرح هذه الأساسيات من الصفر.

## 1. الهدف التحريري

تقديم سلسلة متتابعة تُنتج تطبيقًا واحدًا قابلًا للتثبيت، مع جعل كل مقالة تجيب عن سؤال مختلف وتُسلّم ناتجًا محددًا للمقالة التالية. لا تُستخدم السلسلة لإعادة صياغة الأدلة العامة المنشورة في الموقع؛ بل تُستخدم هذه الأدلة كمراجع داخلية عند الحاجة.

لا يمكن ضمان «صفر تكرار 100%» بصورة مطلقة قبل فحص النصوص الكاملة، كما أن أسماء التقنيات والخطوات المشتركة الضرورية قد تتكرر طبيعيًا. المعيار القابل للتحقق هنا هو: **لا تكرار مقصود في الهدف الأساسي أو الشرح التفصيلي أو الأمثلة المطولة أو بنية الأقسام**، مع إجراء مقارنة فعلية قبل اعتماد كل مسودة.

## 2. قواعد تحريرية إلزامية

1. **نية بحث واحدة لكل مقال:** صياغة سؤال رئيسي واحد، ونتيجة عملية واحدة قابلة للفحص. لا يُستهدف أكثر من موضوع أساسي في العنوان نفسه.
2. **حدود واضحة:** لكل مقال قسم «يشمله هذا المقال» وقسم «خارج النطاق» وفق مصفوفة النطاق أدناه.
3. **شرح متدرج لا مُعاد:** يجوز الإشارة إلى مفهوم سابق بجملة قصيرة ورابط داخلي؛ لا يُعاد شرح المفهوم أو نسخ المثال السابق. لا يتجاوز التذكير المفاهيمي الضروري فقرة قصيرة.
4. **أمثلة تراكمية:** استخدام مشروع المهام نفسه وأسماء الملفات نفسها ما لم تتطلب المرحلة تغييرًا موضحًا. كل مقالة تضيف تغييرًا جديدًا فقط، وتذكر الملفات التي تغيّرت.
5. **عدم تكرار الكود:** لا يُعاد عرض ملف كامل سبق عرضه. تُعرض المقاطع الجديدة أو diff صغير، مع تحديد موضع الإضافة. لا يُعاد نشر كتلة كود طويلة لأغراض التذكير.
6. **عدم تكرار المقدمات والخواتيم:** مقدمة كل مقال تصف المشكلة المحددة في مرحلته، والخاتمة تلخّص ناتج المرحلة وتمهّد للخطوة التالية دون إعادة الملخص العام للسلسلة.
7. **عدم تضخيم المحتوى:** لا تُضاف فقرات عامة عن فوائد الويب أو أهمية JavaScript أو تاريخ PWA ما لم تخدم قرارًا عمليًا داخل المرحلة.
8. **المصطلحات الدقيقة:** التفريق بين Web App Manifest وService Worker وCache Storage وIndexedDB. لا يُقال إن manifest وحده يوفّر العمل دون اتصال، ولا إن كل متصفح يضمن تجربة تثبيت متطابقة.
9. **نتائج قابلة للتحقق:** لا تُذكر نتائج اختبار أو درجات أداء أو توافق متصفح إلا بعد اختبار موثق؛ تُذكر البيئة والخطوات والقيود عند الحاجة.
10. **توثيق المصادر:** الاستناد إلى MDN وweb.dev ومراجع المواصفات الرسمية للحقائق المتغيرة أو سلوك المتصفحات. توضع الروابط قرب الادعاء ذي الصلة.
11. **SEO دون حشو:** عنوان وdescription وcanonical فريد لكل صفحة، وكلمة/نية رئيسية واحدة، وH1 واحد، وروابط داخلية سياقية. لا تُكرر الكلمات المفتاحية في كل عنوان فرعي.
12. **روابط داخلية غير تنافسية:** تُربط الأدلة العامة الموجودة كمراجع تأسيسية، بينما تظل المقالة الجديدة متمحورة حول تطبيق المهام والمرحلة المحددة.
13. **العربية وRTL:** الأمثلة والواجهة عربية واتجاهها RTL حيث يلائم ذلك، مع إبقاء أسماء واجهات البرمجة والخصائص البرمجية كما هي.
14. **إتاحة الوصول:** لا تُختزل الإتاحة في مقال الاختبار فقط؛ تُطبّق التسميات والتركيز والتنقل بلوحة المفاتيح في موضع بناء المكوّن، ثم يُختبر الناتج في المرحلة التاسعة.
15. **لا نشر قبل المراجعة:** تُسجّل المقارنة النصية والموضوعية ومراجعة الروابط والبيانات الوصفية قبل دمج أي مقالة.

## 4. المقالات المنشورة ذات الصلة التي يجب مقارنتها

تمت مراجعة فهرس المقالات المنشور في `data/articles.json`، ويحتوي على 53 سجل مقالة في النسخة التي فُحصت. هذه قائمة أولية للمقارنة. جرى فحص النص الكامل للمقالات التالية، إلى جانب بقية القائمة ذات الصلة:

- `html-css-js-roles` — كيف تتعاون HTML وCSS وJavaScript في صفحة الويب؟
- `html-document-structure`، `html-global-attributes-data`، `html-keyboard-accessibility`، `html-links-paths`، `html-responsive-images`، `html-seo-metadata`، `html-text-headings-links`، `html-validation-debugging`، `html-what-is-html`، `html-semantic-seo` — بنية HTML والخصائص والمسارات والاتجاه والإتاحة وmetadata.
- `html-multipage-project` — مشروع HTML متكامل للمبتدئين: بناء موقع من عدة صفحات
- `html-semantic-elements` — عناصر HTML الدلالية
- `html-form-validation-accessibility` و`html-forms-basics` — النماذج والتحقق والإتاحة
- `css-modern-design` و`css-container-queries-guide` — تخطيط CSS والتجاوب
- `javascript-beginners-guide` و`javascript-clean-code` و`javascript-debugging` — أساسيات JavaScript وتنظيمه وتصحيح أخطائه
- `github-pages-deploy` و`git-github-beginners` — النشر وسير عمل Git/GitHub
- `web-performance-core` و`lighthouse-audit-fixes-guide` و`website-quality-audit-checklist` — الأداء والتدقيق
- `mobile-website-quality-testing` و`web-accessibility-checklist` — اختبار الهاتف وإمكانية الوصول
- `html-performance-loading` و`javascript-fetch-api-errors` — تحميل الموارد وطلبات الشبكة
- `arabic-web-typography-guide` و`seo-content-strategy` — تنسيق العربية وSEO التحريري

يجب أن تتضمن المقارنة التالية أيضًا بحثًا في ملفات المقالات عن `localStorage` و`IndexedDB` و`Service Worker` و`Web App Manifest` و`PWA` و`Cache Storage`؛ غيابها من عناوين الفهرس لا يثبت غيابها من نص المقالات.

## 5. بوابة مقارنة النصوص قبل كتابة/اعتماد كل مقال

تُجرى المقارنة على **النص الفعلي** لا العنوان والوصف فقط:

1. جلب ملف HTML الكامل لكل مقالة ذات صلة، واستخراج النص الأساسي مع الحفاظ على العناوين والقوائم والأكواد.
2. مقارنة عنوان المقال الجديد ونيته ومحاوره وترتيب H2/H3 مع المقالات الأقرب.
3. مقارنة الجمل المتشابهة بعد تطبيع المسافات وعلامات الترقيم، مع تجاهل النصوص العامة الثابتة مثل رأس الموقع وتذييله.
4. فحص تكرار الأمثلة البرمجية: كل كتلة كود مطولة يجب أن تكون جديدة أو مبرر إعادة استخدامها واضحًا مع رابط للمصدر الأصلي.
5. تسجيل نتيجة المراجعة في سجل يتضمن: المقال المقترح، المقالات المقارنة، مناطق التشابه، القرار (قبول/تعديل/إعادة تحديد النطاق).
6. إذا ظهر تداخل في الهدف أو الأقسام، تُعدّل زاوية المقال قبل تحريره. إذا ظهر نص منسوخ أو مثال مكرر بلا ضرورة، يُعاد تحريره أو يُستبدل برابط.
7. بعد اكتمال المسودة، تُعاد المقارنة مرة ثانية؛ ثم تُفحص الروابط الداخلية والعنوان والوصف وcanonical وH1 والكود.
8. لا يُستخدم رقم تشابه آلي وحده كدليل على الجودة أو الأصالة؛ تُراجع النتائج يدويًا لأن أسماء API والمصطلحات التقنية قد تتكرر بحق.

### معيار القبول

- لا يوجد مقال منشور يجيب بالفعل عن السؤال الأساسي نفسه وبالعمق نفسه دون قيمة إضافية واضحة.
- لا توجد فقرات أو أمثلة مطولة منقولة من المقالات المنشورة بلا ضرورة تقنية.
- كل تشابه ضروري (مثل أسماء API أو تذكير قصير) محدود ومبرر.
- لكل مقال ناتج جديد واضح، وروابط سياقية للمحتوى السابق بدل إعادة شرحه.

## 6. مراحل التنفيذ

- **المرحلة A — تثبيت قواعد التحرير والنطاق:** هذا الملف هو المرجع الملزم للسلسلة.
- **المرحلة B — فحص النصوص الفعلية:** جلب المقالات المنشورة ذات الصلة ومقارنة النصوص كاملة قبل كتابة المسودات.
- **المرحلة C — اعتماد موجز تحريري لكل مقال:** كلمة/نية رئيسية، الوعد، المخطط، حدود النطاق، المصادر، الروابط الداخلية.
- **المرحلة D — كتابة المقالات بالتتابع:** لا يبدأ المقال التالي قبل تثبيت ناتج المقال السابق ومراجعة التداخل.
- **المرحلة E — مراجعة نهائية وبناء الموقع:** التحقق من metadata والروابط والاختبارات والبناء وخريطة الموقع، ثم التحقق من النشر الحي.

## 7. متطلبات صفحة المقال على MSEO

- اتّباع قالب HTML والـCSS والـJavaScript الحاليين في الموقع؛ لا تُنشأ منظومة تصميم أو سكربت عام جديد.
- الحفاظ على العربية وRTL والبنية الدلالية.
- إضافة العنوان والوصف وcanonical وOpen Graph وفق نمط المقالات الحالية.
- ربط المقال بالفئة المناسبة و2–4 مقالات ذات صلة عندما تكون الروابط مفيدة فعلاً.
- عدم تعديل ملفات الفهرس أو خريطة الموقع المولدة يدويًا؛ تشغيل أوامر البناء والاختبارات المعتمدة بعد إضافة المقال.
- لا يُعلن اكتمال النشر قبل نجاح الاختبارات وGitHub Actions والتحقق من الصفحة المنشورة.

### نتيجة المرحلة B — الفحص الأولي

- تمت قراءة النص الكامل لـ31 ملف HTML ذي صلة أو مجاور، بما في ذلك العناوين الفرعية وأعداد ظهور المصطلحات المستهدفة.
- أظهر الفحص أن أكبر مناطق التداخل المحتملة هي: CSS والتجاوب (المقال 3)، أساسيات JavaScript (المقال 4)، اختبار الهاتف (المقال 8)، تدقيق الجودة/الإتاحة/الأداء (المقال 9)، ونشر GitHub Pages (المقال 10). لذلك فُرضت حدود نطاق أضيق لهذه المقالات في المصفوفة.
- لم تُظهر عمليات البحث النصي في ملفات المستودع عن `localStorage` و`IndexedDB` و`Service Worker` و`PWA` و`offline` نتائج مطابقة عبر بحث GitHub؛ لكن هذا **ليس إثباتًا نهائيًا لغيابها**، لأن البحث قد لا يغطي كل المحتوى أو المصطلحات البديلة. شمل الفحص الكامل 31 ملفًا من أصل 53، مع تركيز على المقالات الأقرب موضوعيًا.
- لم تُكتب المسودات بعد، ولذلك لا يمكن إصدار حكم على التطابق النصي الفعلي بينها وبين المنشور. تظل إعادة المقارنة بعد كتابة كل مسودة شرطًا إلزاميًا.
- **قرار المرحلة:** اعتماد الخطة التحريرية، والانتقال إلى إعداد موجزات المقالات؛ لا يُعلن انعدام التكرار النهائي قبل تدقيق المسودات نفسها.
