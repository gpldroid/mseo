تاريخ الجرد: 25 سبتمبر 2026
نطاق الجرد: الصفحة الرئيسية، 9 مقالات، 13 صفحة داخل pages، data/articles.json، sitemap.xml وrobots.txt.
الهدف التحريري: محتوى عربي أصلي ومفيد وسهل القراءة أولًا، ثم محسن لمحركات البحث دون حشو كلمات مفتاحية أو إنتاج آلي واسع منخفض القيمة.

الصفحات التصنيفية الست الرئيسية لديها عنوان ووصف وcanonical وH1، لكن النص التعريفي قصير، ولذلك ستحتاج إلى وصف تحريري مفيد يشرح الموضوع ويقود القارئ إلى المحتوى ذي الصلة بدل الاكتفاء بسرد المقالات.

### البنية العامة

- الصفحة الرئيسية تحتوي على عنوان ووصف وcanonical وOpen Graph وTwitter وWebSite JSON-LD.
- المقالات تحتوي على canonical وArticle JSON-LD، لكنها تستخدم حاليًا مؤلفًا من نوع Organization باسم MSEO Editorial بدل المؤلف البشري المعتمد.
- جميع المقالات تحتوي على H1 واحد، وعدة H2، وقسم مصادر وروابط موثوقة، وقسم «اقرأ أيضًا».
- data/articles.json يحتوي على البيانات الأساسية للمقالات لكنه لا يحتوي حاليًا على اسم المؤلف أو تاريخ النشر/التعديل.
- sitemap.xml يغطي الصفحة الرئيسية والمقالات وصفحات الموقع الحالية.
- robots.txt يسمح بالزحف العام ويمنع pages/admin.html وarticle.html.

## 2. الخطة التحريرية الموحدة

لن نستخدم قالبًا آليًا يكرر الكلمات المفتاحية. كل مقال سيمر بنفس منهج العمل، وليس بنفس النص أو الصياغة:

1. تحديد سؤال القارئ الحقيقي ونية البحث.
2. كتابة مقدمة تجيب مبكرًا عن السؤال وتوضح ما سيستفيده القارئ.
3. تقسيم الموضوع إلى أقسام منطقية، مع استخدام H2/H3 عندما يخدم القراءة.
4. إضافة أمثلة وكود وخطوات أو قرارات عملية حيث تكون مناسبة.
5. ذكر القيود والاستثناءات والأخطاء الشائعة بدل تقديم نصائح عامة فقط.
6. إضافة روابط داخلية سياقية إلى مقالات مرتبطة فعلًا.
7. استخدام المصادر الأصلية الموثوقة، خصوصًا وثائق المطورين وGoogle وMDN عند الحاجة.
8. إنهاء المقال بخلاصة عملية أو خطوة تالية مفيدة، وليس بتكرار الكلمات المفتاحية.
9. مراجعة اللغة العربية: وضوح، تنوع في الجمل، مصطلحات تقنية دقيقة، وعدم التصنع في الأسلوب.
10. مراجعة SEO بعد اكتمال النص، لا أثناء كتابة كل جملة.

## 3. سياسة الكلمات المفتاحية

- لا يوجد «عدد كلمات مفتاحية» مستهدف.
- الكلمة الأساسية تظهر حيث تكون طبيعية: العنوان، المقدمة عند الحاجة، عناوين مناسبة، والنص.
- المرادفات والمصطلحات المرتبطة تستخدم لخدمة المعنى، لا لزيادة التكرار.
- لا قوائم كلمات مخفية، ولا فقرات مصطنعة، ولا تكرار متعمد.
- لا ننشئ صفحات متعددة تستهدف استعلامات متشابهة إذا كانت لا تضيف قيمة مستقلة.

## 4. قالب SEO الفني الموحد للمقالات

كل مقال سيحتفظ بالهوية البصرية الحالية، ويستهدف البنية التالية:

- title واضح ومحدد.
- meta description مفيدة ومكتوبة للقارئ.
- canonical صحيح.
- Open Graph وTwitter متوافقان مع المحتوى.
- H1 واحد يطابق موضوع الصفحة دون تكرار آلي.
- BlogPosting أو Article JSON-LD وفق طبيعة الصفحة.
- headline وdescription وimage وdatePublished وdateModified وauthor وmainEntityOfPage وpublisher عندما تكون البيانات متاحة.
- المؤلف: Person باسم عماد الدين لمراني مع رابط صفحة مؤلف حقيقية.
- لا نضيف sameAs أو بيانات خبرة أو حسابات اجتماعية غير موجودة فعليًا.
- BreadcrumbList عندما تكون مناسبة ومطابقة للمحتوى المرئي.
- روابط داخلية حقيقية وذات صلة.
- صور مع alt وصفي غير محشو بالكلمات المفتاحية.

## 5. صفحة المؤلف

سننشئ صفحة مؤلف مستقلة باسم عماد الدين لمراني وتكون مرجعًا موحدًا للمؤلف في المقالات.

ستتضمن:
- اسم المؤلف كما يظهر في المقالات.
- نبذة حقيقية وغير مبالغ فيها.
- روابط إلى المقالات المنشورة.
- ProfilePage JSON-LD عندما تكون البيانات المتاحة كافية.
- استخدام الصفحة كرابط author.url في Article/BlogPosting.

لن نضيف مؤهلات أو خبرات أو حسابات اجتماعية غير موثقة.

## 6. خريطة الربط الداخلي

سنربط المقالات بحسب الموضوع بدل وضع روابط عشوائية:

- الذكاء الاصطناعي ↔ بناء المواقع ↔ Prompts للمطورين.
- HTML الدلالي ↔ SEO التقني ↔ البيانات المنظمة.
- CSS ↔ JavaScript ↔ أداء المواقع.
- استراتيجية المحتوى ↔ البيانات المنظمة ↔ البنية التقنية.
- GitHub Pages ↔ SEO الفني ↔ الأداء.

وستبقى صفحة التصنيف نقطة تجميع للمقالات، بينما المقال نفسه يقود القارئ إلى المقال التالي المنطقي.

## 7. أولويات إعادة التحرير

### الدفعة الأولى
1. استراتيجية محتوى SEO.
2. البيانات المنظمة Schema.
3. إنشاء المواقع بالذكاء الاصطناعي.
4. Prompts للبرمجة بالذكاء الاصطناعي.
5. HTML الدلالي.

### الدفعة الثانية
6. أداء المواقع وCore Web Vitals.
7. JavaScript وتنظيم الكود.
8. CSS الحديث.
9. GitHub Pages.

هذا ترتيب تنفيذ تحريري، وليس ترتيبًا لجودة المقالات أو توقعات الترتيب في Google.

## 8. صفحات التصنيفات

سيتم توحيدها على نموذج واحد:
- عنوان تصنيف واضح.
- وصف أصلي يشرح المجال.
- H1 واحد.
- مقدمة قصيرة مفيدة.
- قائمة المقالات المرتبطة.
- روابط إلى التصنيفات المجاورة عند وجود علاقة حقيقية.
- عدم إنشاء نصوص طويلة فقط لزيادة حجم الصفحة.

## 9. الصفحات غير المقالية

- About: تصبح الصفحة المرجعية للموقع والمؤلف والهدف التحريري.
- Contact: معلومات اتصال واضحة ومباشرة.
- Privacy / Terms: تبقى صفحات قانونية مستقلة ولا نحمّلها كلمات مفتاحية تجارية.
- Tools / AI Assistant: يتم تحسين الوصف وفق الوظيفة الفعلية للصفحة، مع تجنب ادعاءات لا تدعمها الصفحة.
- Admin: تبقى خارج الفهرسة وفق الإعداد الحالي.

## 10. ما لن نفعله

- لا نضمن المركز الأول أو «الصدارة».
- لا نستخدم keyword stuffing.
- لا ننشئ عشرات الصفحات المتشابهة آليًا.
- لا نغيّر تواريخ المقالات فقط لتبدو أحدث.
- لا نضع تقييمات أو مراجعات أو خبرات وهمية.
- لا نضيف FAQ بهدف الحصول على نتيجة غنية لم تعد متاحة كميزة عامة.
- لا نغيّر التصميم الحالي Soft UI / Neumorphism أثناء مشروع SEO هذا إلا إذا ظهر سبب تقني واضح.
- لا نحول المقالات إلى نصوص آلية متشابهة في البنية والصياغة.

## 11. معيار قبول كل مقال بعد إعادة التحرير

قبل اعتماد أي مقال:
- هل أجاب عن سؤال واضح؟
- هل يستطيع القارئ تنفيذ شيء مفيد بعد قراءته؟
- هل توجد معلومات أو أمثلة لا يحصل عليها القارئ من مجرد إعادة صياغة نتائج البحث؟
- هل اللغة طبيعية وسهلة القراءة؟
- هل العناوين تخدم القراءة؟
- هل الروابط الداخلية منطقية؟
- هل المصادر مناسبة ويمكن التحقق منها؟
- هل metadata تعكس المحتوى فعلًا؟
- هل structured data تطابق ما يظهر للمستخدم؟
- هل هناك أي تكرار أو حشو يمكن حذفه؟
