# الموجزات التحريرية المعتمدة — سلسلة PWA

هذه الموجزات تُنفّذ قواعد `docs/pwa-series-editorial-plan.md`. وهي مواصفات تحريرية وليست مقالات نهائية. لا يبدأ تحرير مقال إلا بعد التحقق من نطاقه ومراجعة الملفات ذات الصلة، ثم يعاد فحص النص بعد اكتماله.

## معايير مشتركة

- مشروع واحد: قائمة مهام عربية باسم «مهامي»، وملفات متراكمة لا تُعاد كتابتها كاملة في كل مقال.
- أسلوب الشرح: الهدف، التنفيذ، لماذا هذا القرار، اختبار النتيجة، حدود الحل، ثم الخطوة التالية.
- كل مثال برمجي يوضح تغييرًا جديدًا في المرحلة الحالية فقط.
- لا تكرار لقسم «ما هي HTML/CSS/JavaScript؟» ولا تاريخ PWA.
- مراجع رسمية عند الحاجة: MDN Web Docs، web.dev، مواصفات W3C/WHATWG، ووثائق GitHub Pages.
- لكل صفحة HTML: title وdescription وcanonical وOpen Graph وH1 واحد وروابط داخلية سياقية.
- كلمات البحث أدناه اتجاه تحريري مقترح وليست ادعاءً عن حجم البحث؛ يجب التحقق منها ببيانات البحث الفعلية عند توفرها.

## 1. التخطيط والبنية

**العنوان:** كيف تخطط لبناء تطبيق ويب متكامل؟ تحليل المتطلبات وتصميم بنية المشروع من الصفر  
**نية البحث:** تنظيم مشروع ويب عملي قبل كتابة الكود.  
**الوعد:** الخروج بنطاق واضح، بنية ملفات، ومعايير قبول قابلة للاختبار.  
**الكلمة/العبارة الأساسية المقترحة:** تخطيط مشروع تطبيق ويب  
**مخطط H2:**
1. ما الذي سيحلّه تطبيق «مهامي» وما الذي لن يفعله؟
2. قصص استخدام ومعايير قبول قصيرة
3. فصل الواجهة والسلوك والتخزين وملفات PWA مستقبلًا
4. هيكل الملفات ومسؤولية كل ملف
5. خطة المراحل ونقاط التحقق
**الناتج:** قائمة متطلبات وملفات فارغة/هيكل أولي.  
**روابط داخلية مناسبة:** `html-css-js-roles`، `html-multipage-project`.  
**خارج النطاق:** أي شرح تفصيلي للعناصر أو CSS أو CRUD أو IndexedDB أو النشر.  
**تميّز المقال:** قرار معماري ومواصفات إنجاز، لا «بناء موقع من الصفر» عام.

## 2. بنية HTML

**العنوان:** إنشاء واجهة تطبيق إدارة المهام باستخدام HTML الدلالي ومكونات الواجهة  
**نية البحث:** إنشاء DOM واضح لواجهة مهام عربية.  
**الكلمة/العبارة الأساسية المقترحة:** واجهة تطبيق إدارة مهام HTML  
**مخطط H2:**
1. تحويل متطلبات المقال الأول إلى عناصر واجهة
2. رأس التطبيق ومنطقة المحتوى الرئيسية
3. نموذج إضافة المهمة وحقوله وتسمياته
4. قائمة المهام والحالات الفارغة ورسائل الحالة
5. اختبار البنية والتنقل بلوحة المفاتيح
**الناتج:** ملف HTML دلالي يعمل دون اعتماد على CSS أو سلوك JavaScript.  
**روابط داخلية مناسبة:** `html-semantic-elements`، `html-forms-basics`، `html-form-validation-accessibility`.  
**خارج النطاق:** درس عام في جميع عناصر HTML، أنماط CSS كاملة، معالجة البيانات أو حفظها.  
**تميّز المقال:** يشرح قرارات DOM الخاصة بواجهة «مهامي» فقط.

## 3. تنسيق CSS وRTL

**العنوان:** تصميم تطبيق ويب متجاوب باستخدام CSS: واجهة عربية تعمل على الهاتف والحاسوب  
**نية البحث:** تطبيق تنسيق متجاوب على واجهة مشروع موجودة.  
**الكلمة/العبارة الأساسية المقترحة:** تصميم تطبيق ويب متجاوب بالعربية  
**مخطط H2:**
1. تحديد tokens للألوان والمسافات والخطوط
2. ضبط الاتجاه RTL ومحاذاة المحتوى
3. تخطيط القائمة والنموذج حسب عرض الحاوية
4. حالات الهاتف والحاسوب دون نقاط توقف عشوائية
5. التركيز المرئي، الأهداف اللمسية، والحركة المخفّضة
6. اختبار الواجهة بمحتوى طويل وحالات فارغة
**الناتج:** ملف CSS خاص بالمشروع مع صور/لقطات قبل وبعد إن توفرت فعليًا.  
**روابط داخلية مناسبة:** `css-modern-design`، `css-container-queries-guide`، `arabic-web-typography-guide` إن كان مناسبًا.  
**خارج النطاق:** شرح Grid/Flexbox من البداية أو دليل تصميم عام.  
**تميّز المقال:** توثيق قرارات التصميم المستخدمة في الواجهة الحالية.

## 4. منطق JavaScript داخل الجلسة

**العنوان:** برمجة تطبيق إدارة المهام باستخدام JavaScript: الإضافة والتعديل والحذف والفلترة  
**نية البحث:** بناء وظائف CRUD لتطبيق قائمة مهام.  
**الكلمة/العبارة الأساسية المقترحة:** تطبيق مهام JavaScript  
**مخطط H2:**
1. نموذج الحالة وشكل كائن المهمة
2. ربط النموذج بالأحداث والتحقق من المدخلات
3. عرض القائمة بأمان وتحديث DOM
4. الإضافة والتعديل والحذف
5. الفلترة وحالات عدم وجود نتائج
6. اختبارات يدوية للحالات الأساسية
**الناتج:** وظائف المهام تعمل خلال جلسة الصفحة فقط؛ يصرّح المقال أن البيانات ستُفقد عند إعادة التحميل قبل مرحلة التخزين.  
**روابط داخلية مناسبة:** `javascript-beginners-guide`، `javascript-clean-code`، `javascript-debugging`.  
**خارج النطاق:** شرح أساسيات اللغة، Fetch API، قاعدة بيانات أو caching.  
**تميّز المقال:** وظائف المنتج، وليس تعليم JavaScript بصورة شاملة.

## 5. التخزين الدائم باستخدام IndexedDB

**العنوان:** حفظ بيانات تطبيق الويب باستخدام IndexedDB: الاحتفاظ بالمهام بعد إغلاق المتصفح  
**نية البحث:** حفظ عناصر التطبيق في قاعدة بيانات المتصفح.  
**الكلمة/العبارة الأساسية المقترحة:** IndexedDB JavaScript حفظ البيانات  
**مخطط H2:**
1. متى تحتاج المهام إلى تخزين دائم؟
2. تصميم object store ومفتاح السجل
3. فتح قاعدة البيانات وترقيتها بأمان
4. عمليات الإضافة والتعديل والحذف والقراءة
5. مزامنة واجهة التطبيق مع النتائج غير المتزامنة
6. التعامل مع رفض التخزين أو أخطائه
7. اختبار إعادة الفتح واستمرارية البيانات
**الناتج:** المهام تبقى بعد إغلاق الصفحة وإعادة فتحها في البيئة نفسها، مع توضيح حدود التخزين المحلي.  
**روابط داخلية مناسبة:** `javascript-beginners-guide`، `javascript-debugging` عند الحاجة فقط.  
**خارج النطاق:** Cache Storage، تخزين موارد HTML/CSS/JS للعمل دون اتصال، مزامنة سحابية.  
**تميّز المقال:** بيانات المستخدم المنظمة؛ ليست cache لملفات التطبيق.

## 6. Web App Manifest والتثبيت

**العنوان:** تحويل موقعك إلى PWA: إعداد Web App Manifest والأيقونات وخصائص التثبيت  
**نية البحث:** إعداد تعريف التطبيق القابل للتثبيت.  
**الكلمة/العبارة الأساسية المقترحة:** Web App Manifest PWA  
**مخطط H2:**
1. ما الدور المحدد للـmanifest؟
2. إعداد name وshort_name وstart_url وscope وdisplay
3. إعداد الأيقونات وأحجامها والمسارات
4. ربط الملف والتحقق من تحميله
5. فحص متطلبات التثبيت حسب المتصفح
6. ما الذي لا يقدمه manifest وحده؟
**الناتج:** manifest صالح وأيقونات ومسارات قابلة للتحقق؛ لا يُدّعى العمل دون اتصال في هذه المرحلة.  
**روابط داخلية مناسبة:** `html-document-structure` إن كان متاحًا ومفيدًا.  
**خارج النطاق:** دورة حياة Service Worker وCache Storage وIndexedDB.  
**تميّز المقال:** تعريف التطبيق والتثبيت فقط.

## 7. Service Worker والعمل دون اتصال

**العنوان:** شرح Service Worker عمليًا: جعل تطبيق الويب يعمل دون اتصال بالإنترنت  
**نية البحث:** إعداد cache لملفات تطبيق PWA والتعامل مع انقطاع الشبكة.  
**الكلمة/العبارة الأساسية المقترحة:** Service Worker offline PWA  
**مخطط H2:**
1. دور Service Worker وحدود مسؤوليته
2. التسجيل والنطاق ودورة الحياة
3. قائمة موارد ثابتة يجب تخزينها
4. تثبيت cache وإدارة إصدارها
5. تقديم الموارد عند انقطاع الشبكة
6. تحديث الموارد القديمة وتجنب cache عالق
7. اختبار التثبيت والتحديث والعمل دون اتصال
**الناتج:** shell التطبيق يفتح دون اتصال بعد تحميله وتخزين موارده بنجاح؛ توضيح أن ذلك لا يعني مزامنة أو حفظ بيانات سحابيًا.  
**روابط داخلية مناسبة:** مقال manifest السابق، ومقال IndexedDB السابق.  
**خارج النطاق:** شرح manifest من البداية، حفظ المهام في cache بدل IndexedDB، مزامنة خلفية متقدمة.  
**تميّز المقال:** دورة حياة العامل وcache موارد التطبيق.

## 8. تجربة PWA على جهاز حقيقي

**العنوان:** تجربة تطبيق PWA على الهاتف: التثبيت والتنقل واللمس وإدارة حالات الاتصال  
**نية البحث:** اختبار سلوك PWA بعد التثبيت على الهاتف.  
**الكلمة/العبارة الأساسية المقترحة:** اختبار PWA على الهاتف  
**مخطط H2:**
1. متطلبات الاختبار على HTTPS أو localhost
2. التثبيت من المتصفح وما يختلف بين الأنظمة
3. التحقق من وضع standalone والفتح من الأيقونة
4. اختبار التمرير واللمس ولوحة المفاتيح
5. تجربة انقطاع الاتصال وعودته
6. إزالة التثبيت وإعادة التثبيت والتحقق من التحديث
**الناتج:** سجل اختبار فعلي بحسب الأجهزة والمتصفحات التي جُرّبت، دون ادعاء تغطية أنظمة لم تُختبر.  
**روابط داخلية مناسبة:** `mobile-website-quality-testing` كمرجع عام، والمقالين 6 و7 من السلسلة.  
**خارج النطاق:** قائمة عامة لاختبار كل موقع، إعادة شرح CSS أو Service Worker.  
**تميّز المقال:** دورة تثبيت واستخدام PWA، لا جودة الهاتف عمومًا.

## 9. اختبار الجاهزية

**العنوان:** اختبار تطبيق الويب قبل الإطلاق: تصحيح الأخطاء وقياس الأداء وإمكانية الوصول  
**نية البحث:** تقرير جاهزية لإطلاق النسخة الحالية.  
**الكلمة/العبارة الأساسية المقترحة:** اختبار تطبيق ويب قبل الإطلاق  
**مخطط H2:**
1. مصفوفة الاختبارات حسب ميزة التطبيق
2. حالات إدخال غير صالح وفشل التخزين
3. حالات التحديث وcache القديمة والعمل دون اتصال
4. التنقل بلوحة المفاتيح ورسائل الحالة
5. فحص الأداء والموارد الثقيلة
6. سجل العيوب ومعيار الإطلاق أو المنع
**الناتج:** جدول نتائج فعلية؛ تُوسم الاختبارات غير المنفذة بأنها غير مختبرة.  
**روابط داخلية مناسبة:** `lighthouse-audit-fixes-guide`، `web-performance-core`، `web-accessibility-checklist`، `mobile-website-quality-testing`.  
**خارج النطاق:** إعادة شرح كل أداة أو نسخ قوائم التحقق العامة.  
**تميّز المقال:** مصفوفة اختبار مشروع «مهامي» ومعايير قرار واضحة.

## 10. النشر على GitHub Pages

**العنوان:** نشر تطبيق PWA على GitHub Pages: الإعداد النهائي والتحقق من جاهزية الإنتاج  
**نية البحث:** نشر مشروع PWA في مسار مشروع GitHub Pages والتحقق من سلوكه المنشور.  
**الكلمة/العبارة الأساسية المقترحة:** نشر PWA على GitHub Pages  
**مخطط H2:**
1. مراجعة بنية الملفات قبل النشر
2. ضبط المسارات النسبية وstart_url وscope
3. تفعيل النشر والتحقق من HTTPS
4. اختبار manifest والأيقونات وService Worker على الرابط المنشور
5. اختبار التحديث بعد إصدار جديد
6. قائمة قبول نهائية وخطة تراجع
**الناتج:** رابط نشر فعلي فقط بعد نجاحه؛ لا تُخترع نتائج أو روابط.  
**روابط داخلية مناسبة:** `github-pages-deploy`، `git-github-beginners`، ومقالات 6–9 من السلسلة.  
**خارج النطاق:** تعليم Git من البداية أو إعادة دليل النشر العام.  
**تميّز المقال:** قيود المسار والتخزين المؤقت والتحقق من PWA المنشور.

## قائمة قبول كل موجز قبل كتابة المقال

- [ ] النية الأساسية ليست نسخة من مقال منشور.
- [ ] حدود «داخل النطاق/خارجه» محددة.
- [ ] المقالات الأقرب مذكورة وروابطها ستُستخدم بدل إعادة شرحها.
- [ ] مخطط H2 لا يعيد ترتيب أقسام مقال منشور.
- [ ] الأمثلة المطلوبة جديدة ومتصلة بالمشروع نفسه.
- [ ] المصادر الرسمية محددة للادعاءات التقنية.
- [ ] نتيجة المقال قابلة للتحقق قبل الانتقال إلى المرحلة التالية.
