# النشر عبر GitHub Pages

## المنصة المعتمدة

يُنشر FastSEO عبر **GitHub Pages** باستخدام GitHub Actions.

- الموقع: https://fastseo.site/
- ملف سير العمل: `.github/workflows/deploy.yml`

لا تستخدم Netlify أو أي منصة نشر أخرى لهذا المشروع دون موافقة صريحة.

## متى يعمل سير النشر؟

- عند فتح Pull Request يستهدف `main`: بناء وفحص فقط، دون نشر.
- عند الدفع إلى `main`: بناء وفحص ثم نشر GitHub Pages.
- عند التشغيل اليدوي: يتيح workflow_dispatch تشغيل سير العمل وفق إعداداته الحالية.

## خطوات البناء

1. جلب ملفات المستودع.
2. تثبيت Hugo Extended وNode.js 22.
3. تثبيت اعتماديات npm.
4. توليد CSS عبر `npm run build:css`.
5. تجهيز ملفات المحتوى وفهرس البحث عبر `npm run prepare:content`.
6. بناء Hugo إلى `dist/`.
7. تشغيل `npm run verify` للتحقق من المخرجات.
8. رفع artifact ونشره إلى GitHub Pages عند الدفع إلى `main`.

يمكن تنفيذ نفس المسار محلياً باستخدام:

```bash
npm install
npm run build
```

## فهرس البحث

يُنشأ `static/search-index.json` من `data/articles.json` أثناء تجهيز المحتوى. ويتضمن سجلات المقالات والتصنيفات والموضوعات الفرعية والوسوم. يتحقق سكربت الفحص من وجود الفهرس واكتمال سجلات المقالات والتصنيفات.

لا تعدّل الفهرس يدوياً. إذا تغيرت بيانات المقالات، أعد تشغيل `npm run prepare:content` أو `npm run build`.

## ما الذي يتحقق منه الفحص؟

يتحقق `scripts/verify-build.mjs` من ملفات الموقع الأساسية، وCSS وJavaScript، ووسوم SEO، وفهرس البحث، ووجود المقالات والصفحات، وأرشيفات التصنيفات وبطاقاتها وروابطها، إضافة إلى عناصر التخطيط المشتركة.

نجاح الفحص يؤكد الشروط البرمجية التي يغطيها السكربت، لكنه لا يغني عن الفحص البصري واختبار الموقع المنشور من متصفح فعلي.

## قائمة تحقق بعد النشر

- افتح الصفحة الرئيسية وتأكد من ظهور Header والبحث.
- جرّب البحث بعنوان مقال وباسم تصنيف.
- افتح عدة مقالات وصفحات أدوات.
- افتح صفحات التصنيفات وتأكد من ظهور المقالات الصحيحة.
- تحقق من الصور وبطاقات المقالات.
- افتح `/search-index.json` وتأكد من استجابة الملف.
- تحقق من `/sitemap.xml` و`/robots.txt`.
- راجع سجل Actions وتأكد من نجاح البناء والنشر.
- اختبر الموقع على الهاتف والحاسوب.

## استكشاف الأخطاء

- **فشل تجهيز المحتوى:** تحقق من JSON في `data/articles.json` ووجود ملفات HTML المشار إليها.
- **فهرس بحث قديم أو ناقص:** أعد تشغيل `npm run prepare:content` ثم البناء.
- **مقال أو صفحة مفقودة:** تحقق من slug ومسار المصدر.
- **صورة مفقودة:** راجع مسار الصورة وحقول `image` و`socialImage`.
- **فشل التحقق:** اقرأ رسائل `scripts/verify-build.mjs` ولا تتجاوز الشروط دون معرفة السبب.
- **فشل النشر:** راجع سجل Actions وإعدادات Pages وبيئة `github-pages`.

## ملاحظة حول الواجهة

التصميم الحالي يعتمد الوضع الفاتح فقط. البحث عنصر ضمن Header ويُغذّى من فهرس JSON ثابت؛ لا يحتاج إلى خدمة بحث خارجية.
