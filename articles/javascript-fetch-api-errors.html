استخدام Fetch API في JavaScript: التعامل الصحيح مع الاستجابات والأخطاء

تعلم طلب البيانات من API باستخدام fetch وasync/await، والتحقق من status، ومعالجة JSON والأخطاء بطريقة قابلة للصيانة.

ما الذي تفعله Fetch API؟

تسمح Fetch API بإرسال طلبات HTTP من JavaScript واستقبال نتائجها دون إيقاف بقية الصفحة. ويمكن استخدامها لجلب JSON أو إرسال بيانات إلى خدمة ويب، لكن اكتمال الوعد بنجاح لا يعني أن حالة HTTP نفسها ناجحة؛ لذلك يجب فحص الاستجابة قبل التعامل مع محتواها.

مثال آمن لجلب JSON

async function loadUsers() {
  try {
    const response = await fetch("/api/users");
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    const users = await response.json();
    return users;
  } catch (error) {
    console.error("تعذر تحميل المستخدمين:", error);
    throw error;
  }
}
يوضح المثال فصل طلب الشبكة عن التحقق من الحالة وتحويل الجسم إلى JSON.

لماذا نتحقق من response.ok؟

ترفض fetch الوعد عادةً عند تعذر الاتصال أو فشل الطلب على مستوى الشبكة، لكنها لا تعتبر حالات مثل 404 و500 أخطاءً ترفض الوعد تلقائيًا. افحص response.ok أو response.status صراحةً، ثم قرر كيف سيتعامل التطبيق مع الحالة قبل قراءة البيانات.

التعامل مع JSON غير الصالح

ليس مضمونًا أن يحتوي كل رد على JSON صالح؛ فقد تكون الاستجابة فارغة أو يعيد الخادم نصًا مختلفًا عن المتوقع. وقد يفشل response.json() عند التحليل، لذا افصل هذا النوع من الأخطاء عن فشل الشبكة وحالات HTTP، كي تعرض رسالة مناسبة وتسهّل تشخيص السبب.

إلغاء الطلبات الطويلة

استخدم AbortController عندما يتغير البحث بسرعة أو يغادر المستخدم الشاشة. مرّر signal إلى fetch ثم استدعِ abort عند الحاجة. هذا يساعد على منع عرض نتائج قديمة بعد وصول طلب أحدث.

الأمان وCORS

لا تضع مفاتيح سرية في JavaScript المرسل إلى المتصفح. سياسة CORS يحددها الخادم، ولا ينبغي محاولة تجاوزها من جهة العميل. تحقّق أيضًا من البيانات القادمة قبل إدراجها في DOM، واستخدم textContent بدل innerHTML عند عرض نص غير موثوق.

قائمة اختبار قبل النشر

قبل النشر، جرّب المسار الناجح وحالات 404 وأخطاء الخادم وانقطاع الاتصال وJSON غير الصالح وإلغاء الطلب. أظهر حالة تحميل ورسالة مفهومة عند الفشل، وتجنب تسجيل رموز الدخول أو البيانات الشخصية في وحدة التحكم.

الخلاصة

Fetch تصبح أكثر موثوقية عندما تجمع بين async/await وفحص HTTP ومعالجة التحليل والإلغاء. اجعل مسؤولية الطلب واضحة، وتجنب تكرار منطق الأخطاء في كل مكوّن.
