تحسين سرعة الموقع وCore Web Vitals: دليل عملي للمطورين

خطوات عملية لتحسين أداء صفحات الويب وتقليل JavaScript وتحسين الصور والاستجابة وتجربة المستخدم على الهاتف.

ابدأ بالقياس

ابدأ بالقياس بدل التخمين. استخدم أدوات الأداء لمعرفة ما إذا كان التأخير ناتجًا عن استجابة الخادم أو ملفات كبيرة أو صور ثقيلة أو JavaScript يعرقل التفاعل.

تحسين الصور

قدّم الصور بالحجم المناسب لمكان عرضها، واستخدم صيغة حديثة عندما تدعمها بيئة المشروع. فعّل التحميل الكسول للصور الواقعة أسفل الجزء الظاهر أولًا، مع تجنبه للصور الرئيسية التي يحتاجها العرض المبكر.

تقليل JavaScript

أزل المكتبات والشفرة التي لا يحتاجها الموقع، وخفف المهام التي تعمل أثناء التمرير أو النقر. ويمكن تأجيل تحميل الوظائف الثانوية إلى وقت استخدامها بدل تحميل كل شيء منذ البداية.

CSS والخطوط

تخلّص من قواعد CSS غير المستعملة، ولا تحمّل أوزانًا متعددة للخط ما لم تكن مطلوبة. اختر قيمة مناسبة لـ font-display وراقب ما إذا كان تحميل الخط يؤخر ظهور النص أو يغيّر تخطيط الصفحة.

Core Web Vitals

تابع مؤشرات LCP وINP وCLS لفهم سرعة ظهور المحتوى واستجابة الصفحة واستقرار التخطيط. استخدم النتائج لتحديد تحسينات ملموسة، لا لمجرد الوصول إلى درجة مرتفعة في اختبار منفرد.

الخلاصة

تحسين الأداء دورة متكررة: قِس الوضع الحالي، حدّد السبب، نفّذ إصلاحًا، أعد الاختبار، ثم راقب أثر التغيير بعد النشر.

سير عمل لقياس الأداء

  1. سجّل خط أساس قبل التعديل باستخدام صفحة ممثلة.
  2. حدّد أكبر مورد أو مهمة تسبب التأخير بدل التخمين.
  3. غيّر سببًا واحدًا في كل مرة ثم أعد القياس.
  4. اختبر الوظائف على الهاتف بعد الإصلاح.
  5. راقب بيانات المستخدمين الفعلية بعد النشر، لا نتيجة المختبر وحدها.

يعكس LCP الوقت اللازم لظهور أكبر عنصر محتوى في مساحة العرض، وقد يتأثر بالصورة الرئيسية والخطوط وزمن استجابة الخادم. أما INP فيعبّر عن استجابة الصفحة لتفاعلات المستخدم، بينما يقيس CLS مقدار التحولات غير المتوقعة في التخطيط. حدّد أبعاد الصور والعناصر التي تظهر لاحقًا لتقليل القفزات البصرية، واختبر أثر التحميل الكسول قبل تطبيقه على الصورة الرئيسية.

ابدأ بـ PageSpeed Insights وراجع شرح Core Web Vitals في web.dev. سجّل ظروف القياس قبل وبعد الإصلاح حتى تكون المقارنة مفيدة.

ربط القياس بسبب قابل للإصلاح

ابدأ ببيانات المستخدمين الفعلية عندما تكون متاحة، ثم استخدم اختبارات المختبر لتشخيص السبب. مؤشرات Core Web Vitals تقيس جوانب مختلفة من التجربة، لذلك لا يكفي تحسين مؤشر واحد إذا بقيت الصفحة بطيئة أو غير مستقرة في جوانب أخرى.

  • حسّن LCP عبر تقليل تأخر المورد الرئيسي وتقديمه مبكرًا.
  • قلّل CLS بحجز مساحة للصور والإعلانات والعناصر المحمّلة لاحقًا.
  • خفّض INP عبر تقليل العمل الطويل على الخيط الرئيسي وتحسين معالجات الأحداث.
  • اختبر على أجهزة واتصالات أبطأ من جهاز التطوير.

غيّر عاملًا أو مجموعة صغيرة من العوامل في كل مرة، ثم قارن النتائج في ظروف متشابهة. لا تضف preload أو caching أو تقنيات جديدة دون معرفة المورد أو المسار الذي تريد تحسينه.

عالج أكبر عنق زجاجة أولًا

ابدأ بقياس ميداني ومختبري وافصل بين المشكلات. يرتبط LCP غالبًا بسرعة وصول المحتوى الرئيسي، ويركز INP على الاستجابة للتفاعلات، ويقيس CLS الاستقرار البصري. قد يحسن ضغط الصور LCP لكنه لا يعالج وحده شيفرة JavaScript طويلة تسبب بطئًا في التفاعل.

  • حدد عنصر LCP وقلل تأخر وصول مورده.
  • قسّم العمل البرمجي الطويل وقلل JavaScript غير الضروري.
  • احجز مساحة للصور والعناصر التي تظهر لاحقًا لتقليل CLS.
  • قارن بيانات المستخدمين الفعلية بالقياسات المحلية.
  • أعد القياس بعد كل تغيير مهم.

قد تختلف النتائج بين الأجهزة والشبكات؛ اعتمد على اتجاهات البيانات الميدانية مع الاختبارات المعملية ولا تساوِ بين نتيجة أداة واحدة وتجربة كل الزوار.

خطة عمل لتحسين Core Web Vitals وقياس أثر التغيير

تبدأ خطة الأداء من تحديد الصفحة والجزء الذي يبطئ تجربة المستخدم. تختلف أسباب LCP وINP وCLS، لذلك لا تعالجها جميعًا بضغط الصور أو تقليل JavaScript فقط. اجمع بيانات ميدانية عند توفرها، ثم استخدم الاختبارات المعملية لتحديد العنصر أو المهمة المسؤولة.

المؤشرما الذي يقيسه؟أسئلة التشخيص
LCPزمن ظهور المحتوى الرئيسيما عنصر LCP؟ وهل يتأخر اكتشافه أو تحميله؟
INPاستجابة الصفحة لتفاعلات المستخدمهل توجد مهام طويلة أو معالجات أحداث ثقيلة؟
CLSاستقرار التخطيط البصريهل تحجز الصور والخطوط والإعلانات المساحة مسبقًا؟

حسّن LCP وفق السبب

إذا كان العنصر صورة، راجع أبعادها وصيغتها ووقت اكتشافها وأولوية تحميلها. إذا كان نصًا، افحص وقت استجابة الخادم والخطوط والموارد التي تؤخر العرض. لا تضع preload على كل صورة؛ أعطه للموارد الحرجة التي ثبت أن اكتشافها متأخر.

حسّن INP دون كسر التفاعل

قسّم العمل الطويل، وقلل العمليات غير الضرورية داخل أحداث النقر والكتابة، وتجنب تحديث DOM على نطاق واسع عندما يكفي تحديث جزء صغير. إذا كانت الصفحة تعرض نتائج بحث أثناء الكتابة، ففكر في إلغاء الطلبات القديمة أو تأخيرها قليلًا لمنع تنفيذ عمل لا يحتاجه المستخدم. اختبر كل ذلك على جهاز منخفض الأداء، لا على جهاز المطور فقط.

قلل CLS بحجز المساحات

حدّد أبعاد الصور والفيديو، واستخدم مقاييس خط مناسبة لتقليل القفز عند تحميل الخطوط، ولا تدرج عناصر أعلى المحتوى دون حجز مساحة لها. اختبر الصفحة أثناء التحميل البارد، لأن التحرك قد لا يظهر عند إعادة التحميل بعد التخزين المؤقت.

سجل التغييرات

  1. حدد مؤشرًا وسببًا متوقعًا قبل التعديل.
  2. سجّل النتائج الأساسية في ظروف اختبار واضحة.
  3. نفّذ تعديلًا محدودًا واختبر الوظائف.
  4. أعد القياس أكثر من مرة، وقارن بيانات المستخدمين عند توافرها.
  5. وثّق أي أثر جانبي أو مفاضلة بين السرعة والوظيفة.
