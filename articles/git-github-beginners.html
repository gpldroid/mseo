Git وGitHub للمبتدئين: إدارة إصدارات مشاريع الويب خطوة بخطوة

دليل عملي لفهم Git وGitHub وبناء سير عمل بسيط لحفظ تغييرات مشاريع الويب، إنشاء الفروع، مزامنة العمل وفتح Pull Request.

ما الفرق بين Git وGitHub؟

Git هو نظام لإدارة الإصدارات يعمل على جهازك ويسجل تاريخ التغييرات في المشروع. أما GitHub فهو منصة لاستضافة مستودعات Git والتعاون عليها عبر الإنترنت. لذلك يمكنك استخدام Git دون GitHub، لكن الجمع بينهما مفيد عندما تريد نسخة بعيدة من المشروع أو تعمل مع فريق.

مصطلحات Git التي تحتاجها أولًا

  • Repository: مجلد المشروع مع تاريخ التغييرات الذي يديره Git.
  • Commit: لقطة موصوفة من تغييرات تريد تسجيلها في التاريخ.
  • Branch: مسار مستقل للعمل على ميزة أو إصلاح دون تغيير الفرع الأساسي مباشرة.
  • Remote: مستودع بعيد مرتبط بالمشروع المحلي، وغالبًا يكون على GitHub.
  • Push: إرسال الـcommits المحلية إلى المستودع البعيد.
  • Pull: جلب ودمج التغييرات من المستودع البعيد إلى العمل المحلي.
  • Pull Request: طلب لمراجعة تغييرات فرع قبل دمجها في فرع آخر على GitHub.

إنشاء أول مستودع Git

بعد تثبيت Git، انتقل إلى مجلد مشروعك ثم نفّذ git init. بعدها استخدم git status لمعرفة الملفات التي تغيرت، وgit add لاختيار ما سيدخل في الـcommit، ثم git commit لتسجيل التغيير.

git init
git status
git add .
git commit -m "Initial project"

اختر رسائل commits تصف التغيير بوضوح بدل رسائل عامة مثل "update" أو "changes".

ربط المشروع بـGitHub

أنشئ مستودعًا جديدًا على GitHub، ثم اربطه بالمشروع المحلي عبر remote. المثال التالي يستخدم اسم origin وهو الاسم الشائع للمستودع البعيد.

git remote add origin https://github.com/USERNAME/REPOSITORY.git
git branch -M main
git push -u origin main

استبدل الرابط باسم المستخدم والمستودع الفعليين. لا تضع كلمات المرور أو مفاتيح API داخل ملفات المشروع أو في commits.

لماذا نستخدم Branch؟

بدل تنفيذ كل العمل مباشرة على main، أنشئ فرعًا للميزة أو الإصلاح. بهذه الطريقة يبقى الفرع الأساسي أكثر استقرارًا ويمكن مراجعة التغيير قبل دمجه.

git switch -c feature/contact-form
# عدّل الملفات واختبرها
git add .
git commit -m "Add contact form"
git push -u origin feature/contact-form

كيف يعمل Pull Request؟

بعد رفع الفرع إلى GitHub، يمكنك فتح Pull Request من فرع الميزة إلى main. أضف وصفًا يشرح ما تغير، وما الذي اختبرته، وأي نقاط تحتاج مراجعة. بعد المراجعة والاختبارات يمكن دمج التغيير ثم حذف الفرع إذا لم تعد تحتاجه.

متى تستخدم clone وpull؟

استخدم git clone عندما تريد إنشاء نسخة محلية من مستودع موجود. وإذا كان المستودع المحلي موجودًا بالفعل وتريد جلب آخر تغييرات من الفريق، استخدم git pull بعد التأكد من حالة عملك.

git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
git pull

سير عمل بسيط لمشروع ويب

  1. اسحب آخر تغييرات من الفرع الأساسي عند الحاجة.
  2. أنشئ branch باسم يصف المهمة.
  3. عدّل الملفات واختبر الموقع محليًا.
  4. سجّل تغييرات صغيرة وواضحة في commits.
  5. ارفع الفرع إلى GitHub.
  6. افتح Pull Request وراجع التغييرات.
  7. ادمج التغيير بعد اكتمال المراجعة والاختبارات.

أخطاء شائعة عند البداية

  • العمل مباشرة على main في كل مهمة.
  • إنشاء commit واحد ضخم يحتوي تغييرات غير مترابطة.
  • رفع ملفات سرية مثل مفاتيح API أو ملفات إعداد محلية.
  • استخدام git add . دون مراجعة ما سيُسجّل في المشروع.
  • سحب تغييرات جديدة مع وجود عمل محلي غير محفوظ دون فهم حالة الشجرة.

قبل أي عملية حساسة، استخدم git status وراجع الفرق عبر git diff.

Git وGitHub عند نشر موقعك

Git يسجل تطور المشروع، بينما GitHub يمكن أن يكون المستودع المركزي الذي تحفظ فيه النسخ وتراجع التغييرات. إذا كان هدفك التالي هو نشر موقع ثابت على GitHub Pages، فانتقل إلى دليل نشر الموقع على GitHub Pages؛ ذلك المقال يركز على النشر والاستضافة، وليس على أساسيات Git.

الخلاصة

تعلم Git لا يحتاج إلى حفظ عشرات الأوامر من البداية. افهم دورة العمل: تعديل، status، add، commit، branch، push، ثم Pull Request عند التعاون. مع تكرار هذه الدورة ستصبح إدارة إصدارات مشروع الويب عملية طبيعية بدل أن تكون خطوة منفصلة ومربكة.
