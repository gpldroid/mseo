نشر موقع HTML وCSS وJavaScript على GitHub Pages خطوة بخطوة

دليل عملي لنشر موقع ثابت على GitHub Pages، تنظيم الملفات، ضبط المسارات، إضافة sitemap وrobots وتحسين قابلية الفهرسة.

رتّب المشروع قبل النشر

اجعل الصفحة الرئيسية واضحة، وافصل المقالات والصفحات والموارد المشتركة في مجلدات مفهومة. مثلًا يمكن أن يحتوي المشروع على index.html وarticles/ وpages/ وassets/. التنظيم الجيد يقلل أخطاء المسارات ويجعل التحديثات اللاحقة أسهل.

راجع المسارات النسبية

المسار الذي يعمل من الصفحة الرئيسية قد لا يعمل من داخل articles/. إذا احتاج المقال إلى ملف في assets/، فالمسار النسبي يبدأ عادة بـ../assets/. اختبر الروابط والصور وملفات CSS وJavaScript من كل مستوى مهم قبل النشر.

انشر الموقع على GitHub Pages

ارفع المشروع إلى مستودع GitHub، ثم فعّل GitHub Pages من إعدادات Pages واختر مصدر النشر المناسب للمشروع. بعد نجاح النشر، افتح العنوان النهائي عبر HTTPS واختبر الصفحة الرئيسية والمقالات والروابط بدل الاكتفاء بنجاح عملية البناء.

جهّز الأساسيات قبل التفكير في SEO

اجعل لكل صفحة عنوانًا ووصفًا مناسبين، واستخدم canonical عندما يكون ذلك ملائمًا، وحافظ على HTML دلالي وروابط قابلة للزحف. يمكن أن يساعدك دليل HTML الدلالي في هذه المرحلة، بينما يشرح دليل استراتيجية المحتوى كيف تربط الصفحات حول احتياجات حقيقية بدل إنشاء صفحات مكررة.

أضف sitemap وrobots عندما تحتاجهما

أنشئ sitemap.xml يعكس عناوين الصفحات الفعلية، واستخدم robots.txt لتحديد قواعد الزحف التي تقصدها. لا تستخدم robots لمنع صفحة من الظهور كبديل عن فهم الفهرسة؛ افصل بين التحكم في الزحف وإشارات الفهرسة.

اختبر الموقع بعد النشر

افحص الروابط والصور والملفات الثابتة، ثم جرّب الموقع على الهاتف وسطح المكتب. بعد ذلك راقب الأداء والفهرسة عند توفر البيانات. وإذا وجدت صفحة بطيئة، استخدم دليل تحسين الأداء بدل تعديل الملفات عشوائيًا.

الخلاصة

نشر موقع ثابت على GitHub Pages بسيط، لكن الجودة تأتي من التفاصيل: بنية واضحة، مسارات صحيحة، HTTPS، محتوى مفيد واختبار فعلي بعد النشر.
