أداء HTML: التحميل الكسول وdefer وpreload وقياس السرعة

تحسين تحميل موارد الصفحة باستخدام خصائص HTML المناسبة مع فهم trade-offs وتجنب التحسينات العشوائية.

قلّل ما تحمّله الصفحة

يبدأ تحسين الأداء باختيار موارد لازمة فقط، وضغط الصور، وتقليل الملفات غير المستخدمة. لا تضف تلميحات تحميل لمجرد أنها تبدو متقدمة؛ كل تلميح يجب أن يخدم موردًا مهمًا ومحددًا.

التحميل الكسول للصور والإطارات

<img src="images/example.jpg" alt="مثال توضيحي" width="800" height="500" loading="lazy">
<iframe src="https://example.com/embed" title="محتوى مضمّن" loading="lazy"></iframe>

استخدم loading="lazy" للموارد غير المرئية مبدئيًا. لا تؤخر عادةً صورة LCP الرئيسية التي يحتاجها المستخدم عند فتح الصفحة.

تحميل JavaScript

<script src="assets/js/site.js" defer></script>

يحمّل defer الملف بالتوازي مع تحليل HTML وينفذه بعد اكتمال التحليل، مع الحفاظ على ترتيب السكربتات المؤجلة. يختلف سلوكه عن async الذي ينفذ عند جاهزية الملف دون ضمان ترتيب التنفيذ.

تلميحات الموارد

يمكن استخدام preload لمورد حرج معروف، وpreconnect لاتصال خارجي مهم. الإفراط في التلميحات قد ينافس الموارد الأكثر أهمية على النطاق الترددي. قِس قبل التغيير وبعده.

كيف تقيس؟

استخدم أدوات المتصفح وLighthouse وبيانات المستخدم الفعلية عندما تتوفر. راقب مؤشرات مثل LCP وCLS وINP، وافحص الشبكة والأخطاء. تختلف النتائج بحسب الجهاز والشبكة وحالة التخزين المؤقت؛ لا تدّعِ تحسنًا رقميًا دون قياس حقيقي.
