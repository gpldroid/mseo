CSS Container Queries: تصميم مكونات تتكيف مع المساحة المتاحة

شرح عملي لـ container-type و@container لبناء بطاقات ومكونات تتكيف مع عرض الحاوية بدل عرض الشاشة فقط.

لماذا نحتاج Container Queries؟

تعتمد media queries عادةً على خصائص نافذة العرض، لكن المكوّن قد يظهر في شريط جانبي أو عمود ضيق أو مساحة واسعة داخل الصفحة نفسها. Container queries تسمح بتغيير تنسيق العنصر وفق حجم الحاوية التي يحتويها، ما يجعل المكوّن أكثر قابلية لإعادة الاستخدام.

تعريف حاوية للاستعلام

أضف container-type: inline-size إلى العنصر الذي تريد قياس عرضه. هذا ينشئ سياقًا يمكن للاستعلامات أن تقرأ حجمه على المحور المضمّن.

مثال عملي

.product-card-wrapper {
  container-type: inline-size;
}

.product-card {
  display: grid;
  gap: 1rem;
}

@container (min-width: 34rem) {
  .product-card {
    grid-template-columns: 9rem 1fr;
    align-items: center;
  }
}
عند اتساع الحاوية بما يكفي، يتحول محتوى البطاقة إلى عمودين. تأكد أن العنصر المستهدف داخل الحاوية وأن الاستعلام يقيس الحاوية المقصودة.

كيف تختلف عن Media Queries؟

استخدم media queries عندما يعتمد القرار على خصائص الشاشة أو تفضيلات المستخدم مثل reduced motion. استخدم container queries عندما يعتمد تصميم المكوّن على المساحة المتاحة له داخل تخطيط أكبر. يمكن الجمع بين النهجين.

أخطاء شائعة

لا تضف container-type إلى كل عنصر بلا حاجة؛ اختر حدود المكونات التي تحتاج استقلالًا في التخطيط. اختبر الحالات المتوسطة، وتأكد من عدم حدوث قص أو تمرير أفقي. انتبه أيضًا إلى أن بعض أنواع containment لها آثار على التخطيط، لذلك راجع سلوك العنصر في السياق الحقيقي.

اختبار المكوّن في أماكن متعددة

جرّب البطاقة داخل شبكة واسعة وعمود جانبي وهاتف، ثم غيّر عرض الحاوية دون تغيير حجم نافذة المتصفح. هذه طريقة سريعة للتحقق من أن المكوّن يستجيب لحجمه الخاص فعلًا.

الخلاصة

Container queries أداة قوية لبناء واجهات مكوّنية مرنة. ابدأ بمكوّن واحد واضح، وحدد نقاط التحول بناءً على المحتوى لا على أسماء الأجهزة، ثم اختبره ضمن تخطيطات مختلفة.
