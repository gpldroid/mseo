# فاست سيو | FastSEO

منصة عربية للأدلة التقنية وأدوات تحسين محركات البحث وتطوير المواقع والبرمجة والذكاء الاصطناعي.

**الموقع:** https://fastseo.site/  
**المستودع:** https://github.com/gpldroid/mseo  
**النشر:** GitHub Pages باستخدام Hugo (وليس Netlify).

## التقنيات

- **Hugo Extended** لتوليد صفحات الموقع الثابتة.
- **Go Templates** لقوالب الصفحات والمقالات والتصنيفات.
- **Node.js 22** لتجهيز بيانات المحتوى وفحص مخرجات البناء.
- **Tailwind CSS 3** لتوليد طبقة التوافق الخاصة بالتنسيقات القديمة.
- **GitHub Actions** لبناء الموقع والتحقق منه ونشره على GitHub Pages.

## بنية المشروع

| المسار | الاستخدام |
|---|---|
| `hugo.toml` | إعدادات Hugo، عنوان الموقع، اللغة، الروابط الدائمة وبيانات SEO العامة |
| `data/articles.json` | السجل المرجعي لبيانات المقالات، بما فيها العنوان والتصنيف والصور والتواريخ |
| `migration/source/` | ملفات HTML الأصلية للمقالات والصفحات التي تُضمّن عبر shortcode |
| `scripts/prepare-content.mjs` | إعادة توليد ملفات Markdown داخل `content/` اعتماداً على بيانات المصدر |
| `scripts/verify-build.mjs` | التحقق من اكتمال ملفات الموقع المنشور والمقالات والصفحات والبيانات الوصفية |
| `content/` | ملفات محتوى مولّدة؛ لا تعدّلها يدوياً لأنها تُحذف وتُنشأ من جديد أثناء التجهيز |
| `layouts/` | قوالب Hugo وملفات partial وshortcodes |
| `assets/css/` | ملفات CSS المصدرية التي يعالجها Hugo Pipes |
| `assets/js/` | ملفات JavaScript المصدرية |
| `static/` | الملفات العامة التي تُنسخ إلى جذر الموقع أو مساراته كما هي |
| `.github/workflows/deploy.yml` | سير عمل الفحص والبناء والنشر إلى GitHub Pages |

## التشغيل محلياً

المتطلبات:
- Hugo **Extended**.
- Node.js 22 أو إصدار متوافق مع إعداد CI.
- npm.

نفّذ الأوامر من جذر المستودع:

```bash
npm install
npm run build:css
node scripts/prepare-content.mjs
hugo server
```

ثم افتح العنوان المحلي الذي يعرضه Hugo في الطرفية (غالباً `http://localhost:1313/`).

لإنشاء نسخة إنتاج محلية والتحقق منها:

```bash
npm run build:css
node scripts/prepare-content.mjs
hugo --minify --destination ./dist
node scripts/verify-build.mjs ./dist
```

> لا يوجد حالياً أمر `npm run build` أو `npm run dev` في `package.json`. استخدم أوامر Hugo أعلاه كما هي، ولا تفترض وجود سكربتات npm غير معرفة.

## إدارة المقالات والصور

ملف `data/articles.json` هو سجل بيانات المقالات الذي يقرأه سكربت التجهيز. عند إضافة مقال أو تحديث بياناته:

1. حدّث سجل المقال في `data/articles.json` مع الحفاظ على قيمة `slug` فريدة.
2. ضع ملف HTML الأصلي في المسار المتوقع تحت `migration/source/`، وتأكد من تطابق قيمة `file` أو مسار المصدر.
3. حدّث حقول الصورة عند الحاجة: `image` و`thumbnail` و`socialImage` و`imageAlt`.
4. استخدم صورة مخصصة للمقال، ولا تعِد استخدام صورة مقال آخر.
5. شغّل تجهيز المحتوى والبناء وفحص المخرجات قبل فتح Pull Request.

تستخدم بطاقات المقالات قيمة `image`، بينما تستخدم وسوم المشاركة الاجتماعية `socialImage` مع الرجوع إلى `image` عند غيابها. ويُستخدم `imageAlt` للنص البديل. راجع القوالب ذات الصلة في `layouts/partials/` قبل تغيير هذا السلوك.

## التصنيفات والروابط

تُدار التصنيفات من بيانات المقالات وتهيئة taxonomies في `hugo.toml`. يجب أن تشير روابط التصنيف إلى صفحات التصنيف التي يولدها Hugo، لا إلى ملف Sitemap. عند تعديل قوالب التصنيفات أو breadcrumbs، اختبر صفحات التصنيفات وروابط المقالات الناتجة.

## SEO والمشاركة

توجد الإعدادات العامة في `hugo.toml`، وتُنشأ وسوم الصفحة مثل العنوان والوصف وcanonical وOpen Graph وTwitter في قوالب الرأس وSEO داخل `layouts/partials/`. حافظ على:
- عنوان ووصف فريدين وملائمين لكل صفحة.
- رابط canonical صحيح.
- صورة مشاركة صالحة ومناسبة لمحتوى الصفحة.
- نص بديل وصفي للصور.
- Sitemap وrobots.txt وبيانات Schema عند انطباقها.

لا تضع مفاتيح خاصة أو بيانات اعتماد في المستودع. قيم التحقق العامة ومعرّفات القياس المخصصة للموقع تُدار وفق إعدادات المشروع الحالية.

## البناء والنشر

يعمل GitHub Actions عبر `.github/workflows/deploy.yml` عند الدفع إلى `main`، وكذلك عند فتح Pull Request يستهدف `main` (للفحص دون نشر). يتضمن المسار:

1. تثبيت Hugo Extended وNode.js 22.
2. تثبيت اعتماديات npm وبناء CSS.
3. توليد ملفات المحتوى من بيانات المصدر.
4. تنفيذ `hugo --minify`.
5. تشغيل `scripts/verify-build.mjs` على مجلد `dist`.
6. رفع ونشر مخرجات `dist` على GitHub Pages عند الدفع إلى `main`.

النشر المعتمد للمشروع هو **GitHub Pages فقط**. لا تغيّر منصة النشر أو إعدادات Pages إلى مزود آخر دون طلب صريح.
