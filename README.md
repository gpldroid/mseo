# فاست سيو | FastSEO

منصة عربية للأدلة التقنية وأدوات تحسين محركات البحث وتطوير المواقع والبرمجة والذكاء الاصطناعي.

- **الموقع:** https://fastseo.site/
- **المستودع:** https://github.com/gpldroid/mseo
- **التقنية الأساسية:** Hugo Extended
- **النشر:** GitHub Pages عبر GitHub Actions حصراً.

## التقنيات

- **Hugo Extended** لتوليد صفحات الموقع الثابتة.
- **Go Templates** لقوالب الصفحات والمقالات والتصنيفات.
- **Node.js 22** لتجهيز المحتوى وفهرس البحث والتحقق من مخرجات البناء.
- **Tailwind CSS 3** لتوليد ملف توافق التنسيقات القديمة.
- **GitHub Actions** للبناء والفحص والنشر إلى GitHub Pages.

## بنية المشروع

| المسار | الاستخدام |
|---|---|
| `hugo.toml` | إعدادات Hugo وعنوان الموقع واللغة والروابط الدائمة وSEO العام |
| `data/articles.json` | السجل المرجعي لبيانات المقالات والتصنيفات والصور والتواريخ |
| `migration/source/` | ملفات HTML الأصلية للمقالات والصفحات |
| `scripts/prepare-content.mjs` | توليد محتوى Hugo وفهرس البحث من بيانات المصدر |
| `scripts/verify-build.mjs` | فحص المخرجات والمقالات والتصنيفات والبحث وSEO |
| `content/` | ملفات Markdown مولّدة؛ لا تعدّلها يدوياً |
| `layouts/` | قوالب Hugo وملفات partial وshortcodes |
| `assets/css/` | ملفات CSS المصدرية |
| `assets/js/` | ملفات JavaScript المصدرية |
| `static/` | ملفات عامة تنسخ إلى جذر الموقع، ومنها `search-index.json` بعد التجهيز |
| `.github/workflows/deploy.yml` | سير فحص وبناء ونشر GitHub Pages |

## التشغيل محلياً

من جذر المستودع:

```bash
npm install
npm run dev
```

يشغّل الأمر تجهيز CSS والمحتوى ثم خادم Hugo المحلي. افتح العنوان الذي يظهر في الطرفية، غالباً `http://localhost:1313/`.

## بناء نسخة الإنتاج والتحقق منها

```bash
npm install
npm run build
```

ينفذ `build` بالترتيب: بناء CSS، توليد المحتوى وفهرس البحث، بناء Hugo إلى `dist/`، ثم فحص الملفات والروابط والبيانات الأساسية.

يمكن تشغيل كل خطوة على حدة:

```bash
npm run build:css
npm run prepare:content
hugo --minify --destination ./dist
npm run verify
```

يتطلب أمر `verify` وجود مجلد `dist/` تم بناؤه مسبقاً.

## إدارة المقالات والصور

ملف `data/articles.json` هو سجل البيانات المرجعي. لإضافة مقال أو تحديثه:

1. أضف أو حدّث السجل مع الاحتفاظ بقيمة `slug` فريدة وثابتة.
2. أضف ملف HTML الأصلي في المسار المحدد في حقل `file` داخل `migration/source/`.
3. راجع العنوان والوصف والتصنيف والموضوع الفرعي والتاريخ واسم الكاتب.
4. حدّث حقول `image` و`thumbnail` و`socialImage` و`imageAlt` عند الحاجة.
5. استخدم صورة مناسبة ومخصصة للمقال، وتجنب تكرار الصورة بين المقالات.
6. شغّل `npm run build` قبل فتح Pull Request.

لا تعدّل ملفات `content/` الناتجة يدوياً؛ إذ يعيد `scripts/prepare-content.mjs` توليدها من المصدر.

## البحث في المقالات والتصنيفات

يوجد نموذج البحث في Header، ويبحث في عناوين المقالات وأسماء التصنيفات والموضوعات الفرعية والوسوم. تُنشأ بياناته تلقائياً في `static/search-index.json` عند تشغيل `npm run prepare:content`.

- لا تعدّل `search-index.json` يدوياً؛ فهو ملف مولّد.
- عند إضافة مقال أو تغيير تصنيف أو وسم، أعد توليد المحتوى كي يتحدث الفهرس.
- البحث يعمل على بيانات الموقع الثابتة ولا يحتاج إلى خادم بحث خارجي.
- يجب أن يتضمن فهرس البحث كل المقالات والتصنيفات؛ ويتحقق من ذلك `scripts/verify-build.mjs`.

## الواجهة والتصميم

- اتجاه الموقع عربي RTL مع دعم الشاشات الصغيرة والكبيرة.
- النمط المعتمد حالياً هو **الوضع الفاتح فقط**؛ لا يوجد زر لتبديل النمط الداكن.
- البحث جزء من Header ويستخدم زر HTML أصلياً داخل قالب Hugo.
- حافظ على المكونات المشتركة وتجنب تكرار CSS أو JavaScript.

## التصنيفات والروابط

تُدار التصنيفات من بيانات المقالات وتهيئة Hugo. يجب أن تقود روابط التصنيفات إلى أرشيفاتها الفعلية، وأن تعرض صفحات الأرشيف مقالات التصنيف الصحيحة. حافظ على قيم `slug` وروابط المقالات المنشورة لتجنب الروابط المكسورة.

## SEO والمشاركة

توجد الإعدادات العامة في `hugo.toml`، بينما تُنشأ وسوم الصفحة في قوالب `layouts/partials/`. حافظ على:

- عنوان ووصف فريدين وملائمين لكل صفحة.
- رابط canonical صحيح.
- بيانات Open Graph وTwitter وصورة مشاركة صالحة.
- نصوص بديلة وصفية للصور.
- Sitemap وrobots.txt وبيانات Schema عند انطباقها.

لا تضع كلمات مرور أو رموز وصول أو أسراراً في المستودع.

## البناء والنشر

GitHub Actions يبني الموقع ويفحصه عند فتح Pull Request إلى `main`. وعند الدفع إلى `main`، ينشر المخرجات إلى GitHub Pages بعد نجاح الفحوص.

**GitHub Pages هي منصة النشر المعتمدة حصراً.** لا تنقل المشروع إلى Netlify أو أي مزود آخر ولا تغيّر إعدادات النشر دون طلب صريح.

راجع [دليل النشر](docs/DEPLOYMENT.md) و[دليل المساهمة](CONTRIBUTING.md) قبل إجراء تغييرات واسعة.

## سجل التغييرات والإصدارات

راجع [CHANGELOG.md](CHANGELOG.md) لمعرفة التغييرات حسب الإصدار، و[سياسة الإصدارات](docs/RELEASING.md) لمعرفة قواعد SemVer ورسائل الالتزام وإجراءات إصدار نسخة جديدة. يجب تحديث سجل التغييرات مع كل Pull Request يغيّر سلوك الموقع أو محتواه أو بنيته أو عملية بنائه ونشره.
